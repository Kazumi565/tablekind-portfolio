# Guest camera scan and table confirmation

The guest landing page `/guest` shows **Scan table QR** without requiring any account. When tapped, an HTTPS/localhost browser with camera and native QR detection permission reads live video frames on the guest device. The app accepts only this installation's signed reusable table token or an active-session temporary token, either as a token alone or in a same-origin `/` or `/guest` URL with exactly one `join` or `table` query parameter. A scan stops the camera, calls the existing anonymous preview endpoint, and opens a modal **QR scanned successfully** confirmation with the restaurant, branch and table. The modal blocks the page until the guest closes it through **Continue to Table X** or the keyboard. Closing it focuses the nickname field and scrolls the join form into view. The guest supplies a nickname and explicitly taps **Join table**. The interface then announces **Joined Table X** and scrolls that confirmation into view. Scanning alone never creates a guest, starts an order, saves an image or charges money.

The existing backend validates signed printed QR tokens and active, enabled tables. It checks that a printable code still points to the *same* open session on join, using an idempotency key. The short-lived session QR uses the preexisting `/api/join` preview/join path. Invalid, expired, disabled or unopened tables must fail safely. Role and restaurant permissions have not changed. The existing aggregate QR-scan and successful-join counts apply to printable links; no raw camera footage or scanned foreign-code content is stored. Any printed table link can be opened by someone who sees it, so do not expose the printout publicly.

On an unsupported browser, if the camera permission is refused, or if there is no secure context, the guest can paste a link or use their phone's ordinary camera app to open the printed link. This release intentionally uses the browser's `BarcodeDetector` API without a third-party decoder; in-page scanning is therefore **not universal**. It may not work in Safari, Firefox or older browsers. The fallback does not require an account. This release does not upload or decode still photographs and does not use a CDN. No real device compatibility was verified in the authoring environment.

The printed URL contains the *origin where the QR was generated*. A localhost URL and a Tailscale HTTPS URL are different installations **as far as the scanner is concerned**, even if they reach the same database. Print/share from the same HTTPS address the phone uses. Foreign URLs and extra query/fragment parameters are rejected; staff can rotate a printed table code to invalidate old cards. Existing session guests scanning another table must explicitly choose to switch; unpaid obligations do not disappear. A guest on a table can stop the camera or navigate away; browser tracks are released on success, stop, tab hiding or unmount.

Production domain, live email verification and SMS require separately chosen host/provider, domain/DNS and sender ownership, credential management, opt-in and privacy review. They are **not** configured here. Payment, POS and reservations remain TEST/practice only.
